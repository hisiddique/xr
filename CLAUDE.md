## Commands

- Dev: `composer run dev` (serves Laravel + queue + Vite concurrently) or `npm run dev` + `php artisan serve`
- Build assets: `npm run build` — on shared hosting, use `RAYON_NUM_THREADS=1 npm run build` to avoid Rolldown thread pool panic
- Tests: `php artisan test --compact`; single: `php artisan test --compact --filter=testName`
- Format: `vendor/bin/pint --dirty --format agent` (run before finishing PHP edits)
- DB reset with sample data: `php artisan migrate:fresh --seed`
- Production bootstrap: `php artisan db:seed --class=ProductionSeeder --force` (env-driven: `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `ADMIN_NAME`)

## Architecture

**DeliveryCRM** — Laravel 13 + Fortify + Livewire 4 SFC + Flux UI + Tailwind v4. Single app for customers → delivery notes → invoices, with DN→INV conversion, email sending/logging, and dompdf export.

### Routing + pages
- All pages are Livewire SFCs under `resources/views/pages/`, filenames prefixed `⚡` (e.g. `⚡dashboard.blade.php`). Routes bind via `Route::livewire()` in `routes/web.php`.
- `/` redirects to login (guest) or dashboard (auth). Registration is disabled in `config/fortify.php`.
- Admin-only routes (Settings, Reference Data) use the `admin` middleware alias → `RedirectIfNotAdmin`, gated on `User::isAdmin()` which reads the `users.role` enum (`admin`/`staff`).

### Domain model
- `Customer` hasMany `Document`; `Document` hasMany `DocumentItem` and `DocumentEmailLog`. `Document::customer()` uses `withTrashed()` — customers are soft-deleted but their documents must still resolve the relation.
- `Document::type` distinguishes delivery notes vs invoices; scopes `deliveryNotes()` / `invoices()`. Conversion flips a DN to status `converted` and creates a sibling invoice.
- Doc numbers generated by `App\Services\DocumentNumberGenerator` — year-prefixed (`DN-YYYY-0001`, `INV-YYYY-0001`), atomic via transaction + `lockForUpdate`. Prefix and padding come from `Setting`.
- Invoice totals come from `App\Services\DocumentTotalsCalculator` which reads `vat_rate` from `Setting`. Delivery notes have **no prices** — price lives only on invoices.
- `Setting` is a key/value table with a static in-memory cache; `Setting::flushCache()` must be called after writes in the same request.
- Reference data: `LookupTitle`, `LookupCreditTerm`, `LookupCreditLimit`, `LookupUnit`. Units feed the `per` dropdown on document items (stored as string, not FK).

### Livewire + Alpine conventions
- **Flux modals**: open client-side with `$flux.modal('name').show()` (NOT `$dispatch('open-modal')`); close server-side with `Flux::modal('name')->close()` (NOT `dispatch('close-modal')`). Getting this wrong leaves modals stuck open or email/action buttons dead.
- **Line-item repeaters** are Alpine-managed for zero-network add/remove: `x-data="{ rows: @js($items), ... }"`, and `submit()` calls `$wire.set('items', rows, false)` then `$wire.save()`. See `delivery-notes/⚡create.blade.php` and `invoices/⚡edit.blade.php` for the pattern — copy it rather than reverting to `wire:click="addItem"`.
- **Hero header pattern** (show pages): `relative` card wrapper, `rounded-t-2xl` gradient band, `absolute left-6 top-N` icon/avatar badge, title row + action buttons as a single flex row. Avoid `overflow-hidden` on the wrapper (clips the gradient in dark mode).
- SPA feel: all in-app links use `wire:navigate`. Gmail-style hotkeys (`g c`, `g d`, `g i`, `?`, `n`) live in an Alpine store wired into the layout.

### Company branding
- Logo upload on CRM Settings uses `WithFileUploads`, stored to the `public` disk under `company-logos/`. PDF templates read via local filesystem path (dompdf requirement); emails use `asset('storage/...')`.

### Shared hosting deployment
- Root `.htaccess` rewrites all traffic to `public/` and blocks framework directories. It intentionally does **not** block `/storage` (public uploads need it) and does **not** force HTTPS (provider handles it). Do not re-add either without confirming.
